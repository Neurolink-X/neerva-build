# Bulk catalog media sourcing and local delivery

Static product images, brand previews and logos render only local /images/catalog assets. Vendor URLs remain metadata for sourcing and attribution, never automatic storefront image requests. Existing private merchant media signed URLs are first-party Supabase storage, not vendor hotlinks; that delivery path is unchanged.

The bulk workflow enumerates all families with at least one variant lacking a usable local actual reference. P0 publicly discoverable orderable categories first; P1 other public products; P2 direct-only accessories. Traffic metrics are not available, so no invented popularity ranks. Existing source hints are collected per variant, including failed vendor links. Wikimedia licensed candidates are downloaded to a separate review artifact, resized to WebP, fingerprinted and deduplicated. All matches need visual identity and permission review before being copied into public assets. Generic illustration briefs are created only for unbranded types; these are not images and do not count as coverage. No generated branded pack art. No external network calls from the storefront for these static assets, no paid image API, no production DB change.

Review workflow: open the HTML review and CSV, check each candidate against product and manufacturer information, approve only exact family/type matches with rights and checksum evidence, import into existing reviewed local manifest, run catalog audit and CI. Run --plan-only for offline worklist. An audit that passes does not mean missing photography has been resolved. Existing actual missing photos remain until imports are verified.
