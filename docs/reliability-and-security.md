# Bounded recovery and security
- Public read pages retry their React boundary once per path per tab per ten minutes, only while online and visible. No root-layout auto reload, no storage clearing and no automatic payment/order resubmission.
- The authenticated operations helper rejects non-API and external destinations and refuses redirects. GET only: one transient retry for 502/503/504 or eligible network/timeout failure, with jitter and same user/token confirmation. No retry after explicit 429/403 or mutations; existing same-account 401 refresh remains bounded. Other callers are not automatically covered.
- Existing role/RLS, rate limiting, release contract, dependency audits and incident monitor remain intact. Browser recovery is not proof that a server incident is resolved. No automatic source edits, privilege changes, deployment retries or security bypass.
- CI local-browser performance target LCP 2.5s, CLS .1, TTFB .8s; severe ceilings 8s/.25/4s block smoke. Missing samples are reported, not treated as measured success. Local timings are not actual field measurements.
- Security header checks run in browser CI; service worker script revalidates rather than serving stale code. CSP is currently restrictive for framing/forms/objects but not a full script-src policy; test a report-only nonce policy before enforcing it.
- Remaining: production field telemetry/alerting, privileged account MFA enforcement, CSP rollout, penetration tests, independent backups/restore drills and reviewed rollback procedures. No promise of uninterrupted operation or immunity from attackers.
